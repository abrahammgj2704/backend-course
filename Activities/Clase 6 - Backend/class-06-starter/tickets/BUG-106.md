# BUG-106 — Una colección filtrada vacía responde 404

Reportado por: equipo de soporte
Severidad: media
Estado: abierto

## Síntoma

Cuando un filtro válido de colección no tiene coincidencias, `GET /requests` devuelve `404`.

Pasos para reproducir (con la semilla del taller):

1. Inicia sesión como `ana.requester.seed@example.test`.
2. Solicita `GET /requests?status=closed` con su token.
3. Observa la respuesta.

Ana no tiene solicitudes cerradas, así que el filtro es válido y no coincide con ninguna.

## Comportamiento esperado

Una colección válida sin coincidencias debe devolver:

```http
200 OK
```

```json
[]
```

Una colección vacía NO es un recurso ausente. `404` es para un recurso
individual que no existe (o no debe revelarse) — consulta el contrato de la
clase 3 para colecciones.

## Criterio de aceptación

1. `GET /requests?status=closed` (como Ana) responde `200` con `[]`.
2. El resto de la suite sigue pasando.
3. Una prueba de regresión fija este comportamiento para que no vuelva a aparecer de forma silenciosa.
